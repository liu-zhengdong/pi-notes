# 首版验证记录

## 结论与范围

已跑通：安装本地 Pi package、配置目录、预览与默认注入、修改后的刷新，以及 AI 从文件夹入口逐层找到并读取深层笔记。

验证环境：Pi 0.85.1、Node.js 26.1.0、macOS / arm64。测试隔离了 Pi 配置，没有把本插件安装到用户的真实全局配置，也没有迁移现有 USER。

自动化检查与直接审阅分开进行：下面的测试通过后，还直接查看了完整出站 system/instructions 文本、模型工具调用与回答，以及真实终端渲染的字符网格。

尚未验证：Windows / Linux、其他 Pi 版本、长会话压缩与恢复/分支、与其他提示词改写插件的组合。zg 本身、Obsidian 应用内渲染和用户的真实笔记库不在此次测试范围内。

## 自动化验证

### 类型与单元测试

- `npm run check`：通过 TypeScript 检查。
- `npm test`：22 项通过，无跳过。
- LSP situational tools 在本会话无法激活，因此类型检查使用实际运行的 `tsc --noEmit`，未声称获得 LSP 诊断。

覆盖属性解析、BOM/CRLF、多行 purpose、无属性笔记、两种注入模式、原文保留、根层发现、缓存更新、原子替换、创建/删除、切换目录、文件权限、配置持久化、精确 UTF-8 预算边界、终端换行与滚动。

反向输入实跑的拒绝清单：

- 带引号的 `"false"` / `"true"`、数字形式的 defaultopen。
- 重复字段、损坏 YAML、非映射 frontmatter、非文本 description / purpose。
- YAML 别名引用、自定义标签、缺少 frontmatter 结束分隔符。
- 超长 frontmatter、全文文件超限、笔记块总量超限、预算差一个字节。
- 不可读文件/目录、损坏 JSON、相对配置路径、非法预算与未知配置字段。

另确认隐藏文件、符号链接、非 Markdown 文件、深层 `defaultopen: true` 不会进入默认笔记正文。被拒笔记保留路径与原因；失败后没有复用旧正文。

### 真实 Pi + 本地模型端

`npm run test:integration` 在隔离配置中原样执行 `pi install .`，随后启动真正的 Pi RPC 进程。最终一次使用 8 个本地 HTTP 模型请求，检查：

- package 自动发现 `/notes`；空格/中文路径设置、错误路径不覆盖有效配置。
- 预览笔记块与真实 HTTP 请求中的 system 文本逐字一致。
- 两种模式都有 purpose，原系统提示保留，连续两轮不重复注入。
- 编辑、新建、删除和属性损坏在下一轮生效。
- `/new` 对应的 RPC 新会话、切换目录、停用、损坏配置与错误提示。
- 预览和默认笔记块不作为独立消息写进对话历史。
- print / JSON 模式下，`/notes preview` 只向 stderr 输出笔记，stdout 保持空白或合法 JSONL；无需发起模型请求。

最终记录：`.artifacts/integration-1789463099909/raw/`。

## 真实模型与实际产物审阅

### 模型按需读取

`npm run test:live` 使用已有 `openai-codex/gpt-6-astra`、OAuth 认证的临时副本、low thinking。每次测试限制最多 8 个请求，单次任务等待 150 秒；临时认证文件在退出时删除。

最终样本实际产生 4 个模型请求。模型执行：

1. `ls` 项目目录。
2. `ls` Alpha 子目录。
3. `read` 读取 `验收.md`。
4. 回答口令 `ALPHA-731` 及来源。

直接检查首次出站完整 instructions，确认根 USER 正文、两篇笔记的 purpose、摘要和文件夹路径都正确；其中没有深层验收口令。口令是在工具读取后才出现的，不是预先泄露在默认上下文中。

最终记录：`.artifacts/live-1789463004650/raw/`，包含真实请求、RPC 事件、模型信息和回答。实验前后的 `src/` 哈希一致。

### 终端界面

`npm run test:tui` 在独立 tmux server 内驱动真实 Pi。直接审阅 100×40 与 44×24 两种终端尺寸的渲染字符网格；这是实际 TUI 输出，不是静态模拟界面，也不是操作系统窗口截图。

实测设置目录、选择预览、翻页、窄屏、返回、单次 Enter 执行完整命令、错误路径、损坏笔记、停用和目录失效后的恢复入口，共保存 12 组文本与 ANSI 屏幕记录。

对照初版与修正版：

- 精确命令不再出现重复补全项，第一次 Enter 直接执行。
- 窄屏中优先保留返回与滚动提示；完整路径和正文可逐页查看。
- 目录失效明确显示“配置待检查”，并保留重新设置入口。

最终记录：`.artifacts/tui-1789463004635/raw/`。先前失败的界面记录留在各自的 `.artifacts/tui-*` 目录；自动化驱动的启动/按键时序问题与插件修正的区别见 [设计演进](../DESIGN-Evolution.md)。

## 规模与成本

`npm run bench` 使用合成文件系统样本：1,000 篇根笔记，每篇正文 8 KiB，另有 10,000 篇深层笔记；使用默认 256 KiB 注入预算。

| 扫描 | 耗时 | 读取根笔记文件 | 缓存命中 |
| --- | --- | --- | --- |
| 冷扫描 | 262.78 ms | 1,000 | 0 |
| 未变化的下一次扫描 | 19.40 ms | 0 | 1,000 |
| 修改一篇后 | 17.91 ms | 1 | 999 |

深层笔记未被扫描，默认输出只提供一个 archive 文件夹入口。首次笔记块为 179,307 字节。进程 RSS 观测为 118.8 MiB，包含 Node、依赖、样本创建等，不能解释为插件增量内存。

这是本机合成样本的一轮观测，不代表网络盘、同步盘或所有库规模的延迟保证。记录：`.artifacts/performance/benchmark-final-1789463004.txt`。
